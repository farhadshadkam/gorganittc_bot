# 🎓 سامانه پیش‌ثبت‌نام دوره‌های آموزش مهارتی

سامانه کامل پیش‌ثبت‌نام متقاضیان آموزش‌های مهارتی با **ربات بله + وب‌سایت + پنل مدیریت**، بدون نیاز به سرور و هاست — فقط با **گوگل‌شیت** (دیتابیس و منطق) و **گیت‌هاب** (میزبان سایت).

## 🏗 معماری

```
کاربر بله  ⇄  Bot API بله  ⇄  Google Apps Script  ⇄  گوگل‌شیت (دیتابیس)
بازدیدکننده  ⇄  لندینگ (GitHub Pages)  ⇄  Google Apps Script
ادمین  ⇄  پنل مدیریت (GitHub Pages)  ⇄  Google Apps Script
```

| پوشه/فایل | نقش |
|---|---|
| `index.html` + `assets/js/app.js` | لندینگ عمومی و فرم پیش‌ثبت‌نام وب |
| `admin.html` + `assets/js/admin.js` | پنل مدیریت (داشبورد، ثبت‌نام‌ها، دوره‌ها، پیام بله، گزارش‌ها، تنظیمات) |
| `assets/css/style.css` | استایل مشترک (RTL، سبز/فیروزه‌ای، فونت وزیرمتن) |
| `assets/js/config.js` | ⚙️ تنها فایلی که باید آدرس وب‌اپ Apps Script در آن وارد شود |
| `appscript/*.gs` | کد بک‌اند — در محیط اسکریپت گوگل‌شیت کپی می‌شود |

## 📋 قابلیت‌ها

- **ربات بله:** ثبت‌نام سریع ۶ مرحله‌ای (انتخاب دوره، نام و نام‌خانوادگی، کد ملی با اعتبارسنجی، موبایل، تاریخ تولد شمسی، میزان تحصیلات) + پیش‌پر شدن خودکار اطلاعات کاربران قبلی + کد رهگیری + پیگیری وضعیت
- **لندینگ:** باکس دوره‌های در حال ثبت‌نام با ظرفیت + فرم ۵ مرحله‌ای هم‌راستا با بات (اطلاعات در حافظه مرورگر جمع می‌شود و فقط در پایان یک‌جا ارسال می‌گردد)
- **سرعت:** کش تنظیمات، حذف تماس اضافه در هر کلیک (پاسخ اول، بعد بستن لودینگ دکمه)، لاگ «کارایی» و «تست سرعت» برای یافتن گلوگاه
- **پنل ادمین:** ورود با نام + کد کاربری؛ داشبورد با باکس‌های عددیِ قابل کلیک به تفکیک دوره و وضعیت (منتظر/ثبت‌نام شده/انصراف داده/جواب نداده/سایر)؛ مدیریت دوره‌ها؛ انتقال ثبت‌نام به دوره دیگر؛ تغییر وضعیت تکی/گروهی (بایگانی و بازگشت به «منتظر»)؛ ارسال پیام بله گروهی با گزارش تحویل؛ خروجی CSV؛ گزارش عملیات
- **امنیت:** توکن بات فقط در گوگل‌شیت، نشست ادمین ۳۰ روزه، لاگ کامل عملیات

## 🚀 راه‌اندازی

راهنمای کامل قدم‌به‌قدم در فایل «راهنمای راه‌اندازی.pdf» آمده است. خلاصه:

1. یک گوگل‌شیت جدید بسازید → از منوی «Extensions» → «Apps Script»
2. محتوای فایل‌های `appscript/*.gs` را کپی کنید (+ `appsscript.json` در Project Settings)
3. منوی «⚙️ سامانه ثبت‌نام» → «راه‌اندازی اولیه» را اجرا کنید (برگه‌ها ساخته می‌شوند)
4. Deploy → New deployment → Web app → Access: **Anyone** → آدرس `/exec` را کپی کنید
5. آدرس را در `assets/js/config.js` جایگزین `PASTE_YOUR_APPS_SCRIPT_WEBAPP_URL_HERE` کنید
6. همه فایل‌ها را در یک مخزن گیت‌هاب بریزید → Settings → Pages → فعال‌سازی
7. با @BotFather در بله، بات بسازید و توکن را در پنل ادمین → تنظیمات ذخیره کنید
8. در منوی شیت «⚙️ سامانه ثبت‌نام»: اول «تنظیم آدرس وب‌اپ (/exec)» و بعد «تنظیم Webhook بات» را اجرا کنید

## 🩺 عیب‌یابی: خطای Timeout در تنظیم Webhook / بات جواب نمی‌دهد

اگر هنگام اجرای `setBotWebhook` خطای «Timeout» گرفتید یا بات به `/start` جواب نداد، به این ترتیب چک کنید (کد جدید به‌صورت خودکار ۳ بار تلاش می‌کند):

| علت | راه‌حل |
|---|---|
| آدرس `/dev` به بله داده شده | آدرس `/dev` فقط با لاگین گوگل خودتان کار می‌کند؛ سرور بله به آن دسترسی ندارد. از منوی شیت «تنظیم آدرس وب‌اپ (/exec)» آدرس ختم‌شده به `/exec` را ثبت کنید |
| Deployment با دسترسی Anyone منتشر نشده | Deploy → Manage deployments → مداد (Edit) → Version: New version + **Who has access: Anyone** → Deploy (آدرس `/exec` عوض نمی‌شود) |
| Timeout موقتی شبکهٔ گوگل↔بله | چند دقیقه بعد دوباره `setBotWebhook` را اجرا کنید؛ کد جدید ۳ بار با فاصله تلاش می‌کند |
| باز هم Timeout شد | تابع `botDiagnose` را اجرا کنید (وضعیت توکن، آدرس و Webhook را یک‌جا نشان می‌دهد) و در نهایت منوی شیت ← «نصب تریگر پولینگ (هر ۵ دقیقه)» — بات بدون Webhook هم کار می‌کند، فقط با تأخیر حداکثر ۵ دقیقه |

نکته امنیتی: توکن بات را فقط در برگه Settings یا پنل ادمین نگه دارید و اگر جایی عمومی شده، از @BotFather توکن جدید بگیرید.

## 🐢 چرا پاسخ‌های بات کند است؟ (اینترنت شما مقصر نیست!)

مسیر پیام این است: **گوشی شما ⇄ سرور بله ⇄ سرور گوگل (Apps Script)**. اینترنت شما فقط دو سرِ این مسیر را تحت تأثیر قرار می‌دهد (ارسال پیام و نمایش پاسخ) که کسری از ثانیه است. اگر تأخیر ۱-۲ دقیقه‌ای می‌بینید، علت روی سرورهای میانی است — نه خط اینترنت شما.

**نحوه تشخیص دقیق:** منوی شیت ← «تست سرعت (تشخیص کندی)». این تست حالا دو چیز را جدا نشان می‌دهد:
- **پردازش** — مدت کار خود اسکریپت برای هر پیام (باید ~۱ تا ۳ ثانیه باشد)
- **تأخیر رسیدن از بله** — فاصله بین ارسال کاربر تا رسیدن پیام به وب‌اپ (اگر زیاد است، صف تحویل بله عقب افتاده)

| علت کندی | راه‌حل |
|---|---|
| «پیام در صف انتظار» در عیب‌یابی عددی غیر از صفر است (مثلاً ۸) | صف تحویل بله عقب افتاده (اغلب میراث خطاهای قدیمی آدرس). منوی شیت ← «♻️ پاک‌سازی صف بله و ثبت مجدد Webhook» را اجرا کنید تا صف خالی و فاصله تلاش مجدد بله صفر شود |
| تریگر پولینگ هم‌زمان با Webhook فعال است | دو مسیر موازی = پاسخ تکراری و شلوغی. منوی «حذف تریگرهای پولینگ» را اجرا کنید (عیب‌یابی کامل بات هم هشدارش را می‌دهد) |
| اسکریپت در هر پیام چند بار شیت می‌خواند/می‌نویسد | در کد جدید حل شده: وضعیت مکالمه و پاسخ‌های کاربر در **CacheService** (حافظه گوگل) نگه‌داری می‌شود؛ دوره‌ها و ظرفیت‌ها کش می‌شوند؛ نوشتن در شیت فقط یک‌بار در «تأیید نهایی» انجام می‌شود |

معماری سرعتِ کد فعلی:
- وضعیت مکالمه هر کاربر (مرحله + پاسخ‌ها): `CacheService` با مهلت ۶ ساعت — هیچ خواندن/نوشتن شیت در مراحل پرسش‌وپاسخ انجام نمی‌شود
- دوره‌ها: کش ۱۰ دقیقه‌ای | شمارش ظرفیت هر دوره: کش ۵ دقیقه‌ای (بعد از هر تغییر در پنل، کش خودکار باطل می‌شود)
- ثبت نهایی: فقط ۲ ردیف (کاربر + ثبت‌نام) با کمترین تعداد فراخوانی شیت نوشته می‌شود
- پیام تکراری بله (تلاش مجدد سرور) با `update_id` تشخیص داده شده و دوباره پاسخ نمی‌گیرد
